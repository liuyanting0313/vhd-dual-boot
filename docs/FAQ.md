# FAQ

## 基础

### 这和虚拟机（Hyper-V / VMware / VirtualBox）有什么区别？

| | 虚拟机 | 本项目 |
|---|---|---|
| 性能 | GPU/IO 有损耗 | **零损耗**，裸金属 |
| 系统要求 | 需 HP 支持 | 仅需 Windows + UEFI |
| 隔离性 | 完全隔离 | 共享硬件，互不影响文件 |
| 同时运行 | ✅ 可以 | ❌ 同时只能进一个 |
| 资源占用 | 需分配一半内存 | 不占额外内存 |

**本项目不是虚拟机的替代品**，目标是"能随便折腾的系统环境"。
如果你需要同时跑多个系统，用虚拟机。

### 这和传统双系统（两个分区）区别？

| | 传统双系统 | 本项目 |
|---|---|---|
| 分区 | 需要两个完整分区 | 全部在文件层面 |
| 回滚 | 重装系统 | 删个文件，几秒重来 |
| 空间 | 两份完整系统 | 差分盘初始 4 MB |
| 对硬盘影响 | 改分区表 | **不动分区表** |

### 可以装 Linux 吗？

理论上原生 VHD 启动是 Windows 独有机制。Linux 需要它自己的引导链（GRUB），
本工具包不覆盖。

### Windows 10 可以吗？

原理上可以（Windows 7 起就支持 Native Boot VHD），
但本工具包只在 Windows 11 26300 上验证过。

## 使用

### 我必须先学会 diskpart / bcdedit 吗？

不用。`scripts\` 都封装好了。
但**建议读一遍 [原理](01-concepts.md)**，出问题才知道往哪查。

### 中途必须手动做什么？

只有两处：

1. **把 Windows 部署进 `Base.vhdx`** —— `02` 跑完会打印完整命令
2. **进母盘系统跑 `sysprep`** —— 必须在那个系统内部执行

其余全部脚本化。

### 我可以不改卷标，用其他名字吗？

可以，每条命令加 `-DataLabel "你的卷标"`：

```powershell
.\00-check.ps1 -DataLabel "MyData"
.\01-prepare.ps1 -DataLabel "MyData"
```

### 母盘要多大？

| 用途 | 建议 |
|---|---|
| 只会装几个工具 | 128 GB |
| Office + 开发工具链 | **384 GB**（实测值） |
| 重度使用 | 512 GB+ |

**用 `expandable`，不用 `fixed`。**

### 能建多少个 Work？

没有硬性上限，但：

- 每个都会长大（装同样多的东西，总占用接近 N 倍）
- 启动菜单太长不方便

实际 2-3 个比较合适。

### 可以先在虚拟机里试吗？

**强烈建议。** 见 [沙盒演练](05-daily-use.md#6-沙盒演练强烈建议)。

注意：虚拟机里**测不了 BCD 启动**（需真机），其余都能测。

## 维护

### Work 用久了越来越大，怎么办？

```powershell
# 物理系统，Work 关机
Optimize-VHD -Path 'E:\VHD\Work.vhdx' -Mode Full
```

### 怎么备份？

见 [日常使用 § 3](05-daily-use.md#3-备份)。

核心要点：
- 必须在物理系统，Work 关机
- 必须挂载验证副本能读系统文件
- **备份文件名必须以 `.vhdx` 结尾**

### 母盘需要备份吗？

**需要，而且比 Work 更重要。**

母盘坏了 = 所有子盘失效。而 Work 丢了可以重建，母盘不行。

但母盘只读、不改，所以不容易坏。建完立刻备份一次就行。

### 想给母盘装新软件，怎么办？

唯一安全路径：

```
1. 取消只读（99-rollback.ps1 -Unseal）
2. 启动母盘，装东西
3. 重新 sysprep
4. 重新设只读（04-seal-base.ps1）
5. 重建所有子盘（旧的已失效）
```

**这就是为什么建议母盘一次做好。**

## 故障

### Work 启动不了怎么办？

多数情况下重置就能好：

```powershell
.\05-create-work.ps1 -Reset
```

**数据会丢，但系统能回来。**

如果想知道具体原因，看 [排错](06-troubleshooting.md)。

### 我能不能把 Work.vhdx 拷给别人用？

技术上可以（它是独立完整的差分盘），但：

- 对方必须有**完全相同路径、相同卷 GUID** 的 `Base.vhdx`
- 实际上几乎不可能

**要分享环境，分享脚本 + 母盘构建步骤更靠谱。**

### 会不会把系统搞坏？

**会改 BCD 和系统设置。** 但：

- 每步前都备份 BCD
- 所有改动可回滚
- 不动分区表，不动引导分区文件

**最坏情况**：启动菜单乱了 → `bcdedit /import <备份>` 恢复。

**不会发生**：分区表丢失、C 盘数据丢失。

### 灾难恢复的最短路径

```
1. 进 PE 或另一个能启动的系统
2. bcdedit /import "<备份路径>"
3. 重启
```

所以**每次改 BCD 前一定要导出备份**。`scripts\` 已经自动做了。

## 设计取舍

### 为什么不自动删除旧 Work？

因为"自动删除"很危险。

真实教训：作者写过一个脚本，逻辑是"用完就删目录联接"。
因为权限判断错误，它把自己刚建的联接秒删了，
导致虚拟机无法启动（见 [故障案例](07-real-environment.md#7-一个真实的故障案例)）。

**本工具包的原则：宁可占空间，不自动删东西。**

### 为什么用 diskpart 不用 Hyper-V 模块？

因为 `Get-VHD` / `Get-VM` 需要 **Hyper-V 管理员**权限。
普通管理员跑会静默返回空（见 [pitfalls #5](04-pitfalls.md)）。

`diskpart` 没有这个限制。

### 为什么不支持 Legacy BIOS？

VHD 启动在 Legacy BIOS 下支持很差，实测环境是 UEFI，
没验证过的组合不写进文档。

如果你在 Legacy 环境验证成功，欢迎提 PR。
